## SÉQUENCE D'EXÉCUTION (OBLIGATOIRE)
1️⃣ **Créer les Packages** : Utiliser les outils MCP
   - Créer le package 'Modèle de Domaine' pour toutes les classes
   - Rapporter l'UUID du package

2️⃣ **Créer les Classes** : Utiliser les outils MCP UNE PAR UNE
   - Parser TOUTES les classes du PlantUML
   - Conserver les noms exacts du PlantUML
   - Créer dans le package 'Modèle de Domaine'
   - Rapporter l'UUID de chaque classe
   - 🚨 OBLIGATOIRE : pour chaque classe liée à une exigence, matérialiser le lien «Satisfait» avec l'outil MCP
     `analyst_createRelation` (relation_type="satisfy", source_uuid=<UUID de la classe>, target_uuid=<UUID de l'exigence>,
     module_name="ModelerModule") en un seul appel.
     Sans cette dépendance «Satisfait» réelle dans le modèle, la classe N'EST PAS considérée comme tracée.

3️⃣ **Ajouter les Attributs** : Utiliser les outils MCP POUR CHAQUE CLASSE
   - Ajouter TOUS les attributs du PlantUML
   - Utiliser les types : String, int, boolean, float (compatibles Modelio)
   - NE JAMAIS utiliser : Date, Integer, Boolean
   - Attendre la confirmation de création de classe avant d'ajouter les attributs

4️⃣ **Créer les Associations** : Utiliser les outils MCP POUR CHAQUE RELATION
   - Parser CHAQUE relation : -->, --|>, --o, --*, <|--
   - Créer les associations SEULEMENT après que toutes les classes existent
   - Définir les cardinalités appropriées (1, 0..1, 1..*, 0..*)
   - Nommer les relations de manière significative
   - 🚨 NE PAS IGNORER AUCUNE ASSOCIATION

## CRITICAL TYPE RULES
✅ ALLOWED: String, int, boolean, float
❌ FORBIDDEN: Date, Integer, Boolean, LocalDate

## ASSOCIATION TYPES
- --> = Association
- --|> = Generalization
- --o = Aggregation
- --* = Composition

## RÈGLE DE TRAÇABILITÉ OBLIGATOIRE («Satisfait»)
🚨 Chaque élément de modélisation créé (classe, etc.) qui répond à une exigence DOIT être relié à celle-ci
